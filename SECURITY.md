# Аудит Job Bridge — 10 ноября 2026

Этот отчет описывает исходную проверку перед добавлением QR-входа. Сборка для GitHub дополнительно сравнена с исходниками VPS; QR-вход и миграция индекса проверены локальными тестами. Это не новый сетевой аудит VPS.

## Вывод и границы

В пределах этого ограниченного по времени аудита не подтверждены критические или высокие уязвимости, позволяющие внешнему неавторизованному пользователю захватить панель, выполнить команды или прочитать секреты. Это не сертификат безопасности и не доказательство отсутствия всех уязвимостей.

Найдена и исправлена ошибка отзыва полномочий при отложенной отправке Telegram (оценка: Medium, требуется ранее авторизованный пользователь). Также исправлены дефект Docker-контекста, слабая проверка адреса почты и подготовка репозитория. Закреплен Caddy 2.11.8 и версии транзитивных Python-зависимостей.

Объект: исходный код Python, Dockerfiles, compose.yaml, Caddyfile, правила публикации файлов, политика Chromium, профиль seccomp и тесты. Исходной точкой служил архив версии 14 со всеми известными исправлениями из текущего диалога. Его файлы совпадали с рабочими исходниками перед аудитом.

Методы: ручное чтение приложения и конфигурации; отрицательные запросы через Starlette TestClient; проверка WebSocket-доступа; локальные тесты состояния, гонок, отзыва сессии и дедупликации; проверки Caddy с локальными имитаторами upstream; проверка установленных runtime-зависимостей по OSV. Рабочие Telegram, Gmail и hh.ru не атаковали, сообщения не отправляли, данные пользователей в тестах искусственные. Аудит не менял настройки рабочего VPS.

Не выполнены: новый полный сетевой pentest VPS, аудит SSH/ядра/гипервизора, Docker build/pull (Docker здесь отсутствует), сканирование Debian/Alpine-пакетов внутри реально развернутых образов, динамическая проверка реальной отправки Telegram. Два браузерных теста не исполнялись: локальный Chromium не запускается из-за ограничения socket() окружения. Подключение и рабочие формы на VPS проверялись ранее в ходе настройки, но это не заменяет отдельный браузерный pentest.

## Подтвержденные находки и исправления

### AUTH-01 — отправка после отзыва agent-сессии (Medium)

До исправления HTTP-обработчик проверял cookie один раз, затем ждал Telegram.lock, сеть и чтение истории. Если владелец отзывал доступ в этот промежуток, отложенная операция могла отправиться. Для воспроизведения использованы исходники старого архива и MockTelegram: запрос поставлен в очередь, сессии отозваны, блокировка снята; старый код отправил одно искусственное сообщение.

Теперь HTTP-обработчик передает проверку текущей сессии в Telegram.send. Она выполняется после получения блокировки и повторно после асинхронного чтения истории, перед claim/отправкой. Новые тесты подтверждают отсутствие подключения/отправки при отзыве в очереди и отсутствие отправки при отзыве во время проверки истории.

Ограничение: уже переданный Telegram сетевой запрос может завершиться после отзыва. Отозвать доставленное сообщение или атомарно отменить внешний сервис эта проверка не может. Уже начатая загрузка PDF также относится к операции в полете.

### BUILD-01 — статические файлы исключались из образа

Старый .dockerignore разрешал только bridge/*.py, исключая bridge/static. Новый исходный код создает StaticFiles с проверкой каталога при запуске; свежая сборка без static могла не запустить панель, а старый вариант favicon возвращал бы ошибку. Добавлены разрешения для каталога и его файлов. Это подтвержденный дефект правил сборки; сам Docker build в этой среде не выполнялся.

### CFG-01 — поврежденный адрес проходил проверку CLI (Low, надежность)

Регулярное выражение принимало не-ASCII символы, включая суррогаты после некорректного ввода терминала. Ранее такой адрес действительно препятствовал входу. CLI теперь дополнительно требует ASCII для логина hh.ru и Gmail. Ранее исправленное значение в рабочем томе менять не требуется. Эта проверка не подтверждает, что адрес принадлежит нужному аккаунту: это проверяется владельцем и тестовым входом.

### SUPPLY-01 — версия reverse proxy и воспроизводимость

Плавающий тег caddy:2.11-alpine заменен на caddy:2.11.8-alpine. Ранее загруженный на VPS образ по плавающему тегу мог оставаться старым; точная установленная версия в этом аудите не получена. У Caddy есть advisories, в том числе для сочетания forward_auth и reverse_proxy. Исправление GHSA-6365-7ppr-5r92 опубликовано в 2.11.5. Выпуск 2.11.8 включает более поздние исправления. Не все advisory применимы к нашему Caddyfile: например, у нас нет PHP, file_server для каталога с ключами или root на основе {host}. Захват сервиса через эти advisory не воспроизведен.

Добавлены requirements.lock для app и auth. Dockerfiles используют их. Это фиксация версий, не проверка wheel-хешей и не гарантия против компрометации поставщика. Теги базовых ОС не закреплены digest; их нужно регулярно обновлять и пересобирать образы.

### REPO-01 — защита от случайного добавления рабочих данных

Расширен .gitignore: варианты .env, ключи, PEM, SQLite, Telegram session-файлы, резервные .bak и .before-*, окружения, PDF. Правила не удаляют уже отслеживаемые секреты из Git и его истории. Текущий архив собран из исходников по разрешенным типам и проверен отдельно: рабочих ключей, почтовых настроек, cookies, баз, PDF и резервных копий нет.

## Что проверено

| Область | Результат |
| --- | --- |
| Одноразовый код, повторное использование, срок сессии | Код случайный 192 бит, сессия 256 бит, в SQLite хеши; повторное погашение отклоняется |
| Cookie | Secure, HttpOnly, SameSite=Strict, префикс __Host |
| Owner/agent | Agent не может включать hh_shared или отзывать доступ владельца |
| CSRF | Несовпадающий, отсутствующий и null Origin отклоняются; CORS-разрешений для чужих сайтов нет |
| XSS | Текст сообщений, ошибки, получатели и URL экранируются; предпросмотр привязан к сессии и данным, TTL 15 минут |
| SQL injection / shell injection | SQL параметризован; HTTP-поля не передаются в shell, eval или pickle |
| WebSocket | Без cookie, без разрешения hh_shared и с чужим Origin отклоняется до подключения upstream |
| Публичные файлы | Проверены попытки доступа к .env, secrets, PDF и traversal через /assets; ответы 404 |
| Caddy | Проверены 4 варианта запрета анонимных VNC-ресурсов, 3 варианта закрытого internal URI, авторизованный ресурс без передачи Cookie upstream |
| Дедупликация Telegram | Проверки истории, числового peer ID, конкурентного claim и неизвестного результата проходят; при сбое истории отправка блокируется |
| Gmail | TLS; проверка отправителя и Authentication-Results Google; только свежие UID; неоднозначные коды отклоняются |
| Секреты | Fernet; отдельные ключи/тома app и hh-auth; миграция сохраняет существующий ключ, конфликт останавливает миграцию |
| Контейнеры | Только proxy публикует 80/443; нет docker.sock, privileged, host network или SYS_ADMIN; readonly rootfs и ограниченные ресурсы |

Внутри Docker используются HTTP/WS; защита там опирается на хост и сегментацию, не на взаимный TLS. Профиль seccomp расширяет стандартные разрешения для user namespace sandbox Chromium; ядро остается общей границей доверия. Выполненный локальный тест Caddy использовал бинарник 2.11.7 и имитаторы upstream на случайных loopback-портах, не развернутые контейнеры. Адаптация Caddyfile успешна; новый образ 2.11.8 необходимо проверить при обновлении VPS.

## Проверка зависимостей

pip-audit с базой OSV проверил установленное окружение. В нем присутствуют и инструменты самой рабочей среды; их находки не следует выдавать за зависимости сервиса. Из результата выделено точное замыкание runtime-зависимостей app и hh-auth: 18 пакетов с совпадающими версиями, известных уязвимостей в этом подмножестве не найдено. Машиночитаемый результат: dependency-audit.json.

Не проверены Debian Chromium, noVNC, websockify, OpenSSL ОС и остальные пакеты контейнеров. Результат OSV относится к дате проверки, не к будущим уязвимостям. Требуется актуальный apt-слой сборки: одного запуска закешированного docker build недостаточно для обновления Chromium.

## Результаты тестов

27 тестов: 25 прошли, 2 браузерных пропущены. 8 локальных проверок маршрутизации Caddy прошли. Baseline воспроизведение AUTH-01 подтвердило отправку после отзыва; исправленные тесты подтверждают блокировку до отправки. Telegram полностью имитирован; реальных откликов не было.

## Оставшиеся границы доверия

- Полное управление noVNC дает полномочия пользователя серверного рабочего стола, а не узкую функцию «только отклик». Содержимое hh.ru может содержать prompt injection; проект не умеет отличать полезную инструкцию модели от вредоносной. Серверные разрешения и отзыв доступа важнее обещаний модели.
- Agent-cookie действует до 30 дней, не привязан к личности ChatGPT. Украденная cookie дает соответствующий доступ до отзыва/истечения. Полная утечка ключей или захват VPS/hh-auth позволяет расшифровать почтовые настройки.
- Gmail app password дает доступ к почтовому ящику шире, чем чтение кодов hh.ru. Предпочтителен отдельный почтовый ящик. Шифрование на диске не защищает от захвата работающего процесса с ключом.
- Пароль приложения, Chromium-профиль и Telegram-сессия не попадают в Git; рабочий профиль hh.ru и резюме на диске не являются отдельным зашифрованным хранилищем.
- Между ручной отправкой с телефона и проверкой истории Telegram остается гонка; удаленные из истории сообщения не видны. Абсолютная exactly-once гарантия между независимыми клиентами отсутствует.
- Публичный сервис остается подвержен перегрузке сети/ресурсов. Ограничения тела, числа соединений и контейнеров не заменяют внешнюю защиту от DoS. Внутренние порты нельзя публиковать, полагаясь только на UFW: опубликованные Docker-порты имеют отдельные правила маршрутизации.
- Приватный GitHub-репозиторий не заменяет защиту секретов. Если секрет уже попал в историю, его нужно отозвать/заменить, а не только удалить файл.

## Обновление существующего VPS

Распаковать архив поверх исходников в /home/ratmir/apps. Не удалять .env, secrets или Docker volumes, не выполнять docker compose down -v. Затем:

```bash
cd /home/ratmir/apps/job-bridge
sudo docker compose build --pull --no-cache
sudo docker compose pull proxy
sudo docker compose up -d --force-recreate proxy app hh hh-auth
sudo docker compose ps
sudo docker compose exec proxy caddy version
```

Пересоздание браузера кратковременно прервет экран. Профиль и почтовая настройка сохраняются в прежних томах. Проверить «Сессия hh.ru активна», открыть экран, проверить иконку и PDF. Прежние agent-сессии остаются действительными; их можно отозвать владельцем. Новые защитные изменения не применены к рабочему VPS автоматически.
