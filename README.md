# Job Bridge

Результаты ограниченного по времени аудита: [SECURITY.md](SECURITY.md). История исправлений: [CHANGELOG.md](CHANGELOG.md). В архив не входят `.env`, `secrets/`, PDF и рабочие сессии. Они остаются на VPS.

Панель на VPS для адресных откликов в Telegram и работы с hh.ru. Telegram отправляет текст и, по выбору, PDF от твоего аккаунта. Для hh.ru используется отдельный Chromium с постоянным профилем. Когда сессия заканчивается, сервис может запросить код на привязанную почту и ввести его сам.

## 1. Запуск на VPS

Нужен Linux-сервер с Docker Engine, Docker Compose v2 и Python 3. Для Chromium выдели от 2 ГБ памяти. Создай DNS-запись для домена панели и открой входящие TCP-порты 80 и 443. Caddy получит HTTPS-сертификат автоматически.

Выполни команды из каталога, в который загружен архив.

```bash
unzip job-bridge.zip
cd job-bridge
python3 init.py
sudo python3 secure_setup.py
sudo docker compose up -d --build
sudo docker compose ps
sudo docker compose exec app python -m bridge.cli code owner
```

Скрипт спросит DNS-имя и напечатает адрес панели. Открой его и введи одноразовый код из последней команды. Код действует 10 минут, сессия владельца — 8 часов. Скрипт `secure_setup.py` переносит существующий ключ Telegram из `.env` в `secrets/bridge.key` и создаёт отдельный `secrets/hh.key` для почтовой настройки. Файлы ключей имеют права 0400 и передаются только нужному контейнеру через Docker secrets. Сохраняй каталог `secrets` вместе с резервной копией томов и `.env`. Команды Docker на VPS выполняй с `sudo`.

## 2. Автоматический вход в hh.ru

1. В действующем аккаунте hh.ru открой **Настройки → Личные данные**. Убедись, что там подтверждена почта, через которую открывается именно твой профиль соискателя. Если обычно входишь по SMS, добавь и подтверди почту один раз в этом же профиле.
2. Используй Gmail, который получает письма с кодами hh.ru. Простой вариант — отдельный Gmail, привязанный к hh.ru напрямую. Для пересылки из другого ящика код принимается только если Gmail сохранил проверяемую подпись отправителя hh.ru. Пароль приложения даёт сервису доступ к почтовому ящику по IMAP, поэтому отдельный ящик ограничивает этот доступ.
3. Включи двухэтапную аутентификацию Google и создай [пароль приложения Gmail](https://myaccount.google.com/apppasswords).
4. На VPS выполни команду ниже. Она спросит привязанную к hh.ru почту, адрес Gmail для чтения и пароль приложения. Если привязан Gmail, введи один и тот же адрес дважды. Ввод пароля приложения скрыт. Сервис хранит почтовую настройку зашифрованной в приватном томе. При обновлении прежний JSON автоматически заменяется шифротекстом. Ключ хранится отдельно в `secrets/hh.key`.

```bash
sudo docker compose exec hh-auth python -m hh_auth configure
```

В панели нажми **Проверить вход**. Пока идёт авторизация, экран браузера закрывается. Обнови панель, дождись статуса **Вход восстановлен** или **Сессия hh.ru активна**, затем нажми **Открыть браузер hh.ru**. Для проверки именно восстановления сначала убедись, что профиль Chromium в этой панели разлогинен. Сессия в обычном браузере или приложении телефона не влияет на профиль на VPS.

В серверном браузере вводи адреса hh.ru полностью, с `https://`. Политика Chromium разрешает HTTPS для hh.ru и блокирует остальные адреса; ввод голого домена может привести к заблокированному HTTP-переходу.

Дальше сервер проверяет сессию каждые 10 минут. При разлогине он использует только свежие письма от подтверждённых отправителей hh.ru. На доставку письма отводится до трёх минут. Новый код запрашивается максимум раз в час. Если hh.ru показывает CAPTCHA, дополнительную проверку, регистрацию или незнакомую форму, сервис останавливает автовход до проверки владельцем. Можно войти вручную в серверном Chromium, предварительно закрыв экран для помощника, затем возобновить проверку.

```bash
sudo docker compose exec hh-auth python -m hh_auth pause
sudo docker compose logs --tail 40 hh-auth
sudo docker compose exec hh-auth python -m hh_auth resume
```

Инструкции hh.ru для [входа в аккаунт соискателя](https://feedback.hh.ru/knowledge-base/article/2223). Документация Google для [паролей приложений](https://support.google.com/accounts/answer/185833).

## 3. Telegram и PDF

Получи `api_id` и `api_hash` в разделе **API development tools** на [my.telegram.org](https://my.telegram.org/). Запусти подключение на VPS, введи номер, код Telegram и облачный пароль, если он включён. Код и пароль вводятся только в терминале. Сервис шифрует полученную сессию и использует её при отправке.

```bash
sudo docker compose exec app python -m bridge.cli telegram
```

Если код не приходит, используй QR-вход:

```bash
sudo docker compose exec app python -m bridge.cli telegram --qr
```

Введи api_id и api_hash в терминале. Заранее открой на телефоне Telegram → Настройки → Устройства → Подключить устройство. Сканируй QR на экране компьютера именно этим сканером. QR обновляется при истечении срока, максимум пять показов за запуск. При включенной двухэтапной аутентификации введи облачный пароль в терминале. QR — временный секрет входа; не публикуй его. После сообщения «Telegram подключён.» обнови панель. Формат сохраненной зашифрованной сессии тот же, что при входе по коду. Сообщения при подключении не отправляются.


Положи PDF рядом с `compose.yaml` под именем `resume.pdf` и загрузи его в контейнер. Размер до 10 МБ.

```bash
sudo docker compose exec -T app python -m bridge.cli resume < resume.pdf
```

В панели введи `self` и тестовое сообщение, чтобы проверить доставку в **Избранное**. Поле ссылки можно оставить пустым. После успешного теста повтори отправку с галочкой PDF; повторные тесты в Избранное разрешены, они учитываются в дневном лимите. Для отклика укажи опубликованный работодателем личный `@username`, HTTPS-ссылку вакансии и сопроводительный текст. Проверь предпросмотр и нажми **Отправить в Telegram**. С PDF сопроводительный текст отправляется подписью к файлу. Лимит подписи — 1024 единицы UTF-16. Для сообщения без PDF лимит — 4096.

Перед отправкой панель проверяет личный чат от имени подключённого аккаунта. Любое видимое исходящее сообщение блокирует отклик, даже если ты отправил его вручную с телефона, писал по другой вакансии или раньше общался на другую тему. Чат, в котором есть только входящие сообщения, допускает первый отклик. Если Telegram не даёт проверить всю историю, панель останавливает отправку. Тексты переписки в журнале не сохраняются. Тест в **Избранное** выполняется без проверки истории.

Журнал блокирует повторы через панель по числовому Telegram ID получателя. Это работает для другой вакансии и после смены `@username`. По умолчанию действует лимит 8 попыток в день по Москве. При тайм-ауте после отправки в журнале появляется **нужна сверка**. Сверь результат в Telegram и обнови запись командой `python -m bridge.cli resolve` внутри контейнера `app`. Команда принимает номер записи и `sent`, если сообщение есть в чате, или `failed`, если его точно нет и попытка уже завершилась.

Если ручное сообщение уже удалено из доступной истории или появилось между проверкой и отправкой, панель может его не увидеть.

Создай в настройках Telegram обычную папку с точным названием **Отклики**. После подтверждённой отправки через панель Job Bridge добавит в неё личный диалог с получателем. Если папка отсутствует, название повторяется или Telegram не подтвердил обновление, панель покажет результат отдельно от статуса отправки. Уже отправленный отклик останется в журнале, и повторная отправка будет заблокирована. Для теста в **Избранное** папка не обновляется.

## 4. Доступ помощника

```bash
sudo docker compose exec app python -m bridge.cli code agent
```

Открой панель в браузере, где будет работать помощник, и один раз введи этот код. Сессия помощника действует до 30 дней. Чтобы дать доступ к серверному профилю hh.ru, в панели владельца нажми **Открыть браузер для помощника**. Сессия помощника открывает Telegram-форму и, после явного включения, экран hh.ru. Код владельца, пароль приложения Gmail и данные Telegram CLI держи у себя. Помощнику достаточно доступа к панели.

Кнопка **Отозвать доступ помощника** аннулирует его сессии и одноразовые коды. Серверный профиль hh.ru сохраняется в отдельном томе и переживает штатный перезапуск. Chromium запускается отдельным непривилегированным контейнером с sandbox через Linux user namespaces, отдельным томом профиля и корневой файловой системой только для чтения. Профиль seccomp основан на [профиле Docker](https://github.com/moby/profiles/blob/main/seccomp/default.json) с разрешением `clone`, `setns`, `unshare` и `chroot` для sandbox. Внешние capabilities у контейнера сброшены. Если ядро или AppArmor на VPS запрещают нужные user namespaces, Chromium завершится с ошибкой. Проверь журнал контейнера `hh`. Порты рабочего стола и CDP наружу не публикуются.

## Обновление уже запущенного проекта

Распакуй новый архив в тот же родительский каталог `/home/ratmir/apps`. Затем выполни команды из каталога проекта.

```bash
sudo python3 secure_setup.py
sudo docker compose build --pull
sudo docker compose pull proxy
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail 60 hh hh-auth
```

Перед запуском Chromium сервис захватывает эксклюзивную файловую блокировку тома. После получения блокировки он удаляет оставшиеся от прежнего контейнера служебные ссылки SingletonLock, SingletonSocket и SingletonCookie. Второй экземпляр сервиса с тем же томом ждёт завершения владельца блокировки через штатный перезапуск контейнера. При первом обновлении с версии без этой защиты предварительно останови hh-auth и hh.

Перенос ключа Telegram сохраняет его прежнее значение. Томы данных используются по прежним именам. Чтобы скрытый старый почтовый JSON мигрировал в шифротекст, запусти обновлённый `hh-auth`.

При запуске обновленного приложения прежний индекс журнала отправок автоматически заменяется индексом с исключением для `self`. История, сессии и данные сохраняются.

Перед подтверждением обновления проверь успешный запуск Chromium на VPS по журналу контейнера hh. Локально проверены миграция ключей, шифрование, авторизация и повторные отправки.

В панели включено ограничение 20 попыток входа в минуту с одного IP. Caddy заменяет заголовок с IP клиента перед передачей приложению. Для приложения проверяется имя хоста. Для контейнеров ограничены ресурсы и размер журналов.

Изоляция контейнеров и шифрование защищают отдельные границы доступа. Пользователь с root-доступом к VPS может получить ключи и активные сессии.

## Проверки

На машине с установленным Chromium можно дополнительно запустить браузерный тест с подменённым HTML hh.ru. Тесты не отправляют сообщения и не запрашивают реальные коды.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
RUN_BROWSER_TESTS=1 .venv/bin/python -m unittest discover -s tests -v
```
